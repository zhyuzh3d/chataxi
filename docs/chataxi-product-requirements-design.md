## 1. 产品定位

chataxi 是运行在 HermitApp 中的个人 AI 对话 happ。用户在本机连接自己的模型服务，创建具有独立提示词、模型参数和声音的角色，再进行单聊或有限群聊。产品不提供账号、云同步、角色市场或托管密钥；角色、服务、会话、压缩上下文和 API Key 保存在当前 happ 实例。

chataxi 负责对话体验和有限的供应商协议适配，不取代模型网关。复杂路由、审计、计费、密钥隔离和供应商兼容应由 llmserver 等网关承担。页面保持纯原生 HTML、CSS、JavaScript，无运行时第三方框架、包管理器、编译步骤、远程脚本或 CDN。

完整用户闭环是：添加模型服务 → 创建角色并选择具体模型 → 设置自己的身份资料 → 创建对话 → 输入文字、图片或语音并艾特一位角色回答 → 在长期对话中自动压缩上下文 → 必要时修改消息、压缩内容或从指定回复重新生成。

## 2. 信息架构

底部导航固定为五项，顺序为“对话、角色、模型、我的、设置”，设置始终位于最右侧。每个标签名称只在顶部标题栏显示；内容区不重复英文眉题、大标题和介绍。对话标签顶部显示 chataxi 出租车图标、品牌名和版本号，不显示“对话”标题。

- 对话：全部会话的单一列表、搜索、置顶、草稿摘要和新建入口，不再按单聊、群聊、全部分栏。
- 角色：紧凑角色卡、创建和编辑角色、发起对话。
- 模型：不带图标的“对话模型、朗读模型、语音输入”三个服务分类。
- 我的：全局个人设定，包括用户名称、本地图片头像和加入模型上下文的自我介绍。
- 设置：按“界面、对话、压缩、关于”组织主题、对话偏好、默认语音服务、上下文压缩参数和运行信息。

所有新增、编辑、确认、菜单和选择流程使用同一套自定义底部 Sheet。Sheet 从屏幕底部进入并始终横向铺满屏幕；主 Sheet、二级选择 Sheet 与确认 Sheet 都由视口级弹层根节点挂载，并显式设置左右边界与 100% 宽度，不能依赖旧 WebView 可能忽略的 `inset`。桌面宽屏仍停靠底部，不切换为系统菜单或居中系统对话框。模型、服务、音色、主题等枚举选择也使用叠加在编辑 Sheet 上方的自定义选择 Sheet，不触发系统原生列表菜单。并排按钮使用 Grid 间距或相邻元素外边距，不把 flex-gap 当作唯一间距来源。点击不显示浏览器外框；键盘焦点使用组件内部高亮。

## 3. 首次使用与列表

首次进入的对话空状态显示三个进度：连接模型、创建角色、开始对话。用户选择官方服务商时只需填写该服务商真实要求的凭据，协议和请求地址由注册表固定。点击“获取模型”后读取当前账号实际开放的目录，再在全宽 Sheet 中选择一个具体模型；连接测试成功后只保存这一模型。聚合平台和本地运行时才显示必要的服务地址与模型系列确认；判断不出的目录项进入“未知能力”，由用户选择并承担兼容性判断。

角色卡将头像、名称、具体模型和状态放在紧凑首行。底部“编辑角色”和“开始对话”按钮等宽，均使用图标加文字。对话卡头像在左上对齐，正文与头像保留横向间距；参与者信息统一显示为“群聊 | Alice · Bob · Jane”或“单聊 | Alice”，超长时单行省略。

新建和编辑对话不提供单聊/群聊开关：选择一位角色自动成为单聊，选择两位及以上自动成为群聊。标题为空时按参与角色生成。每个对话直接显示自己的 `recentFullMessages` 滑杆，范围 5–50，默认 10；通用设置不再提供重复的 N 值入口。

## 4. 角色与模型服务

### 4.1 单模型连接与角色配置分层

每个模型卡片只表示一个可调用的具体模型，保存服务商入口、传输协议、模型系列、外部模型 ID、连接状态和验证基线。一个卡片不能保存第二个模型。相同账号的凭据和模型目录单独保存在本机记录中，由多张卡片通过引用复用；“复制添加”复用连接信息并要求重新选择一个模型。角色只引用模型卡片，并独立保存生成或发音参数。

语言模型入口包括 llmserver、OpenAI、DeepSeek、Anthropic Claude、Google Gemini、xAI/Grok、Kimi/Moonshot、GLM/智谱和自定义兼容服务。适配协议为 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages、Gemini GenerateContent 与 Ollama Chat。官方入口固定协议和端点，聚合入口保持自己的外层协议；模型系列只用于能力匹配，不能把聚合平台内的 Claude 等模型改走官方接口。目录结构化能力优先，精确注册表其次，保守分类规则只推荐用途和系列，不创建多模态或高级参数。名称、端点、协议、模型 ID 和自定义 Header 收入默认折叠的“更多设置”。模型卡不显示温度、输出长度、`top_p`、`top_k`、推理强度、图片生成等角色参数。

朗读家族包括 Android 系统朗读、OpenAI TTS、ElevenLabs、豆包语音和自定义 OpenAI 风格 TTS。ElevenLabs 的模型目录与账户音色目录独立读取；密钥缺少 `models_read` 但能够读取音色时，使用包含 Multilingual v2、Flash v2.5 和 Eleven v3 的内置 Text to Speech HTTP 目录并继续执行真实合成测试，不把可用的服务误报为整体失败。服务目录真实返回且声明可做文字转语音的额外模型仍可使用。豆包语音使用最新版 V3 API 的单一 API Key 鉴权，不要求 App ID；所选模型作为资源 ID，内置语音合成 2.0、1.0与声音复刻 2.0、1.0。语音识别家族包括 Android 系统语音识别、OpenAI 语音识别和自定义 multipart 服务。Android 系统语音识别永远保留并作为默认路径，不依赖 GMS、海外账号或运行时模块下载。

API Key 只使用一个可编辑密码输入控件。未聚焦时显示首尾可见、中段固定遮罩，聚焦后编辑真实值，粘贴新密钥会整体替换旧值；旁边提供复制按钮，不提供独立清除开关。修改后的凭据允许直接保存，但在重新连接前标记为待验证，不沿用旧凭据的验证结论；“重新连接并更新目录”使用当前输入刷新目录并验证默认组合。切换家族不会把旧家族密钥带入新家族。自定义 Header 的旧 JSON 不回填到文本框，每个 Header 值同样遮罩显示并可单独复制；留空保留、填写后整体替换，也可明确清除。完整值不进入 HTML、属性、日志或错误信息，只在用户主动复制或实际请求时读取。自定义 Header 禁止覆盖 Host、Content-Length 等传输字段。源码检查覆盖 OpenAI、Gemini 与 xAI 常见密钥格式，防止完整密钥进入版本化文件。

Android 系统语音服务固定保留且不进入第三方服务编辑器。停用正在被通用默认、角色或对话引用的服务前必须先解除引用。角色使用中的 LLM 服务不能删除；删除 TTS 或 ASR 服务时，相关角色、对话和通用默认安全回落到 Android 系统服务。只有连接测试成功才能说明服务可用；已保存密钥但没有模型的语言服务显示为“待获取模型”，其“获取并测试”动作会补取模型、默认启用返回列表，再执行最小聊天测试。

### 4.2 角色设置

角色编辑 Sheet 包含：

- 角色名称、本地图片头像和角色提示词；不再显示快速模板、图标头像、头像颜色、“一句话介绍”或独立选图按钮。头像本身是图库入口，选择后使用独立裁切 Sheet。蓝色正方形及九宫格就是最终取景范围，支持单指拖动、双指捏合、滚轮和按钮缩放；缩放下限保证图片短边不小于方框，位移约束保证方框永远不落到图片外。输出为方形本机媒体。“我的”头像使用同一组件并保留移除头像入口。没有图片时，未填写名称显示用户图标，填写名称后显示名称首字符。
- 对话模型卡片。模型只能从已经通过连接流程的单模型卡片 Sheet 选择，角色不再二次选择服务内模型。
- 温度、最大输出 Token、`top_p`、`top_k`、推理强度和图片生成。控件只在当前模型有明确能力与合法范围时出现；未知或不支持的参数不显示、不保存、不发送。
- 朗读模型卡片、音色和模型专属参数。系统朗读隐藏没有意义的模型层级，但显示 Android 引擎实际提供的语言和音色；其他卡片只有目录中存在可用音色时才显示音色选择，音色提示词仅在模型明确支持时出现。豆包语音模型显示其已登记支持的语速、音调和音量，其他模型不复用这些字段。试听按钮按表单中的即时配置播放“你好！欢迎使用朗读功能。”；必要条件不满足时禁用。
- “跟随通用设置”不复制服务 ID，通用默认变化后角色自动跟随。

Hermit 的系统 TTS 合同提供当前引擎的语言、音色、语速和音调能力，`tts.speak` 可以指定实际音色 ID。chataxi 从系统音色目录生成自定义 Sheet 选择，保存默认组合并用于服务试听和跟随通用设置的角色；引擎未提供的选择项直接隐藏。第三方 TTS 的角色级音色和支持的音色提示词进入实际请求。

## 5. 对话与群聊编排

消息保持用户在右、角色在左，双方头像均为圆形。气泡采用浅黄色主题、常见即时通讯的左右布局和小尖角。显示层把连续空段落收敛为普通换行，使段间距与行间距一致，但不改写持久化文本或模型上下文。模型内容用 `textContent` 渲染，不执行 Markdown HTML。图片最多四张，发送前压缩并受 Hermit 请求体上限约束。文字与附件草稿逐对话保存，离开页面前等待写入完成。

群聊角色点选区属于输入框组件，使用无背景的 `@` 标识和固定单行角色按钮，不显示“全部”。每个角色按钮显示小圆头像和名称；每轮必须且只能选择一位参与角色，名称最多显示五个字符，超长时显示前四个字符加省略号。角色较多时只有角色条局部横向滚动，页面与 Sheet 仍禁止横向滚动。选择写入对话并在下一轮和重新进入时保持。发送文字只调用被艾特角色；不填写文字和图片时也可发送，系统会保存明确的“@角色 请继续回答”用户消息后调用该角色。

每个对话把参与角色第一次从空选择状态选中的角色保存为主持人，并把主持人固定在参与角色顺序首位；移除主持人后，仍在选择顺序中的第一位自动接任。基础设定中的主持人名字后显示“主持”标记，群聊消息中的主持人头像带细亮黄色圆环，对话卡片和顶部参与者名称也始终先显示主持人。群聊输入区右端提供持久化的魔法棒开关，默认关闭；开启后角色条仍可横向滚动，但暂时禁用手工艾特。每次普通发送先用主持人的模型、全部参与角色设定、当前个人设定、共享概要和全部尚未压缩消息执行一次非流式路由，只接受 `{\"role\":\"完整角色名称\"}` 或唯一精确角色名，再由该角色正式回复。路由输出不保存为消息。路由调用失败、超时或格式无效时，从当前全部可用参与角色随机选择一位继续并显示 Toast；用户主动停止不触发随机回复。

每个角色请求的上下文固定为：

1. 本对话全部参与角色的名称与角色提示词，并标明当前发言角色；
2. 用户名称与自我介绍；具体对话的名称、介绍分别在非空时覆盖“我的”对应字段，空字段各自回落到全局值，不做内容合并；头像只用于界面显示，不进入模型上下文；
3. 本对话共享的最近压缩上下文；
4. 摘要覆盖边界之后全部尚未压缩的完整完成消息，其中同时包含用户消息和所有角色回复。N 是每次压缩后必须保留的最近完整消息下限，不是平时截断上下文的上限。

当前角色只执行自己的角色设定，同时理解其他参与者的身份。任何一个角色失败不会删除用户消息或其他已完成回复。停止本轮会跳过未开始角色、把当前回复标记为已停止并忽略迟到结果；已发出的原生网络请求仍可能在供应商侧计费。

## 6. 上下文自动压缩

通用设置保存四项：是否自动压缩、触发总字数、目标字数和压缩提示词。每个对话独立保存 N。摘要文字与摘要边界之后全部未压缩消息的总字数超过阈值，并且未压缩消息多于 N 条时，在下一次角色回答前执行压缩。触发前，全部未压缩消息持续进入角色上下文，不允许因为超过 N 条而静默丢弃；N 只规定压缩完成后仍保留多少条最近完整消息。

单聊由该角色压缩；群聊始终由参与角色列表中的第一位角色使用自己的语言模型压缩，关闭图片生成，并把输出 Token 限制到与目标字数相符的范围。待压缩输入严格由上次共享概要和“当前未压缩消息中除最近 N 条之外的前缀”组成。压缩请求另带全部参与角色的名称与角色介绍，以及当前对话实际生效的用户名称与介绍，资料只帮助模型识别说话者、指代和关系；系统指令明确禁止摘录、概括或故意把这些资料本身写入概要，只有消息中实际形成的事实才可总结。

成功后用一条概要记录保存压缩文本、压缩模型角色、实际覆盖到的最后消息 ID 与时间、累计覆盖消息数、保留 N 和更新时间。第二次压缩把上次概要与上次边界之后、本次最近 N 条之前的新消息合并成概要 2，再把覆盖边界前移；原消息继续保存在设备上。请求期间输入区显示“正在压缩历史上下文 · 角色名”。失败时不移动边界，也不删除历史。

每个对话只维护一份共享压缩内容，后续所有参与角色读取同一份摘要。对话菜单可查看并手工修改最近压缩内容。修改只改变后续模型上下文，不伪装为原始历史。

首次生成压缩内容之前，全部状态完成的消息均可编辑，角色回复也提供独立重新生成按钮。生成压缩内容后，已经进入摘要边界的消息不再提供编辑或重新生成入口；可操作范围是摘要边界之后且位于当前对话最近 N 条内的完成消息。编辑操作只保存文字，不触发模型、不删除任何后续消息。用户需要重新生成角色回复时，另行点击该回复下方按钮；只要目标回复后还有任何用户消息或角色回复，就必须先确认删除全部后续消息，再由原角色重新生成当前回复。删除会同时回收无引用媒体并刷新列表摘要。

## 7. 语音输入与朗读

Android 系统语音识别为默认服务。调用前检查可用性，处理 ready、begin、rms、partial、final、error、end 事件并核对会话 ID；最终文本只填入输入框，不自动发送。模型页提供统一的录音测试 Sheet：系统识别直接显示部分结果和真实 RMS 波形，只有一次性识别能力时调用系统识别界面；第三方识别由 Hermit 录制受管理的 M4A 文件、显示真实录音电平、通过原生 multipart 上传并展示返回文字。每个对话可覆盖语音识别服务、具体模型和语言。

第三方 ASR 通过用户主动选择的不超过 650 KiB 短音频调用 multipart 接口。Hermit 当前没有把录音逻辑文件直接作为 multipart 请求体的公共合同，因此第三方 ASR 不伪装成系统识别的一键持续录音。

朗读服务先读取角色覆盖，再回落到通用默认。ElevenLabs 连接分别获取账户可用的文字转语音模型与分页音色列表，目录权限彼此独立，并在保存前执行一次最短合成。音色返回的高质量基础模型、语言验证模型和微调状态分别保存；这些都是质量和训练元数据，不是兼容白名单，不能据此隐藏账户音色。Professional 音色允许直接选择 v3；界面提示官方所述的 PVC 相似度风险，但不推导协议参数。已弃用且 v3 明确拒绝的 `use_pvc_as_ivc` 绝不发送。豆包语音使用 `X-Api-Key`、模型对应的 `X-Api-Resource-Id` 和唯一请求 ID 调用 V3 HTTP SSE，逐事件解码并合并 Base64 音频；新版控制台密钥路径不显示 App ID 或 Access Token。角色依次选择服务、模型和音色。第三方 TTS 适配器统一处理鉴权、请求体、模型能力、取消、逻辑文件和内联音频播放。

每个对话可以覆盖自动朗读。开启后，最后一位角色的回复自动播放，具体路径由该角色所选服务和模型的实际能力决定，不提供会把已支持能力关闭的手工流式开关。支持流式音频的第三方模型直接消费 HTTP 可读流、SSE 或 WebSocket 返回的 16 位 PCM 分片，累计约三秒后自动开始；播放追上生成时进入等待，新音频到达后不擅自恢复，由用户点击消息播放按钮继续。环境在首个音频分片前不能建立流式通道时回退完整音频；已经开始播放后的流中断不从头重播。

语言模型仍在生成时，ElevenLabs Multilingual v2 与 Flash v2.5 使用 Text-to-Speech WebSocket，Eleven v3 使用 Text-to-Dialogue WebSocket。完整段落形成后立即送入同一连接，返回音频分片直接加入播放队列。OpenAI Speech 和豆包 V3 当前按完整段落发起请求，其中 OpenAI 消费 24 kHz PCM HTTP 流，豆包逐条消费 V3 SSE PCM 数据。两者没有在本适配器中声明增量文字会话能力，但每段音频仍在响应结束前开始播放。Android 系统 TTS 没有增量队列合同，只处理完整回复。

对话右上角喇叭保存该对话的自动朗读静音状态。静音只阻止后续自动朗读，不暂停或停止已经开始的音频，也不禁用消息下方的手工朗读。播放状态独立于静音状态：正在播放时只把图标本身变为高饱和绿色，按钮背景保持透明，即使已经静音；没有播放时使用默认状态色。静音与未静音使用不同图标。

结构化数据优先使用 `hermit.data`，浏览器源码预览降级为 localStorage；媒体 Blob 使用 IndexedDB。消息按 `conversationId:timestamp:id` 排序。超过约 60 KiB 的正文分块保存到 `message-text`，结构化记录保留引用。删除对话级联删除消息、草稿、压缩内容和无引用媒体。

0.4.15 启动时保留已有数据，并补齐对话级个人设定字段。对话消息旁的角色头像无论是图片还是文字占位，点击都直接打开统一的全宽底部“编辑角色”Sheet；保存后当前对话立即更新角色名称、头像、艾特角色条和模型可用状态。用户头像无论是图片、文字还是默认图标，点击都打开“本对话个人设定”Sheet，支持独立名称、头像和介绍；空字段逐项跟随“我的”。下一轮生成从持久存储重新读取全部角色与个人设定，因此新提示词、模型、朗读设置、个人名称和介绍立即生效。

群聊每轮只有被艾特角色拥有发言权。系统提示先声明唯一发言身份，把当前角色设定作为执行指令，把其他参与角色设定放入不可执行的参考区；历史中只有当前角色自己的回复保留 assistant 语义，其他角色回复以带发言者名称的参考消息传入。请求末尾重复本轮唯一发言者，禁止扮演、代替、模拟或续写其他角色以及输出角色署名。若模型仍显式使用其他参与角色的名称作为开头署名，客户端在显示、保存和朗读前拦截该回复，并允许用户重新生成。

## 9. 网络与适配器

普通模型、TTS 和 ASR 请求通过 `app/platform/network.js`，在 Hermit 环境调用 `hermit.network.request`。语言模型和第三方 TTS 的流式路径使用标准 Fetch 可读流、SSE 或供应商 WebSocket；如果 WebView 缺少可读流或供应商跨域策略拒绝，语言模型改用 Hermit 原生完整响应，TTS 在首个音频分片前失败时改用完整音频响应。只允许 HTTP(S)，WebSocket 地址只从已验证的供应商 HTTP(S) 地址推导；公网密钥服务应使用 HTTPS，HTTP 仅用于用户信任的局域网服务。

内部消息统一为 `role/roleName/text/images`，供应商适配器只转换请求和解析结果，不读取 UI 和持久化。Responses 解析 `response.output_text.delta`，Chat Completions 解析 `choices[].delta.content`，Anthropic 解析 `content_block_delta/text_delta`，Gemini 使用 `streamGenerateContent?alt=sse`。完成内容按节流间隔保存，停止任务会中断读取并保留可重试状态。

请求 JSON 控制在 900 KiB 以内，最长超时 120 秒。普通文本链接和注解不会自动加载为图片。模型输出、供应商错误和用户内容不得写入 `innerHTML`；日志不包含 Authorization、Cookie 或完整密钥。

## 10. 视觉与可访问性

界面以中性背景、白色卡片和出租车黄为强调色。标题栏图标与文字、卡片头像与正文、横排按钮都使用明确间距；对话首页在 chataxi 标题后显示当前版本小字。设置页和所有 Sheet 采用直接铺在背景上的沉浸式分区，避免卡片轮廓嵌套。设置页分为“界面、对话、压缩、关于”；关于页使用包内标准图标并显示作者 `zhyuzh3d`。本地运行时连续点击运行方式三次可切换为线上实时运行，线上模式可一键恢复本地运行，选择持久化到 happ 实例。清除数据 Sheet 允许分别选择对话、角色、模型和个人设定，默认全部选中。对话输入区的图片与麦克风按钮相邻并使用 8px 间距。点击消息旁角色头像打开角色编辑 Sheet，点击用户头像打开本对话个人设定 Sheet。移动端底部 Tab 栏从首帧起固定在视口底部，应用外壳预留相同高度，异步初始化不能推动或覆盖它；桌面宽屏再切换为静态侧栏。布局使用统一圆角、边框、间距、按钮高度和语义颜色。触控目标至少 44×44 CSS 像素，正文至少 15px，状态不只依赖颜色；表单有可见标签，异步状态使用 `role=status` 或 `aria-live`。适配安全区、软键盘、横竖屏、深浅主题和减少动效偏好。

聊天只在用户接近底部时自动跟随。用户查看历史时，新回复不会强制抢走滚动位置。底部 Sheet 和页面都不调用系统菜单控件。

## 12. 明确非目标与风险

- 不做账号、云同步、公共角色市场、后台无限互聊、后台录音、代码执行、RAG、MCP 或自动化动作。
- 不把模型营销名称当作能力证明；具体能力由家族目录、模型元数据和实际接口共同决定。
- 手机直存供应商主密钥风险高，推荐通过 llmserver 使用最小权限 Token。
- Hermit 原生网络当前无 SSE；标准 WebView 可读流不可用或被跨域策略拒绝时，回复明确回落为整段兼容输出。
- 群聊每轮只调用被艾特的一位角色，但仍需携带全部参与角色设定；界面不猜测供应商价格。
