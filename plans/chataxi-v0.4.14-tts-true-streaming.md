# chataxi v0.4.14 第三方 TTS 真实流式播放修订

本次修订解决旧实现把语言模型回复按段拆分、但仍等待每段 TTS 完整返回后才播放的问题。支持流式音频的第三方模型现在直接消费响应体音频分片，以 16 位小端 PCM 接入同一个 Web Audio 播放队列；累计约三秒后自动开始，供应不足时按既有交互暂停并允许用户继续。运行环境不能读取流、供应商跨域策略阻断或模型不支持时，自动回退到完整音频路径。

OpenAI Speech 使用 24 kHz PCM HTTP 流；豆包 V3 使用 HTTP SSE 中持续返回的 PCM 数据；ElevenLabs 完整文本使用 HTTP Streaming。语言模型仍在生成时，ElevenLabs Multilingual v2 与 Flash v2.5 使用 Text-to-Speech WebSocket，Eleven v3 使用独立的 Text-to-Dialogue WebSocket，把已经形成的段落持续提交并直接播放返回的 PCM 分片。OpenAI 和豆包目前按完成段落发起独立请求，因为当前接入的接口没有采用增量文字会话合同，但每个请求的音频仍是真实流式播放。

流式能力由服务家族与具体模型共同决定，用户不再手工打开流式开关。群聊按实际回复角色逐次选择路径；同一对话可以同时包含流式第三方角色和完整音频或系统朗读角色。旧 `streamTtsPlayback` 字段保存时清理，不影响现有对话迁移。

版本号为 0.4.14，版本代码为 29。自动化检查覆盖响应结束前开始 PCM 播放、缓冲耗尽后的手工继续、Eleven v3 增量文字 WebSocket、失败前无音频时的完整音频回退，以及原有模型、对话、数据和安全合同。
