# chataxi 0.3.8 xAI 模型发现修订

根因是服务状态、模型发现和聊天测试之间缺少闭环。xAI 家族没有静态模型目录，旧数据可能只保存 API Key 而没有保存模型；服务卡却把它显示为“已配置”，直接点击“测试”时聊天测试拿不到模型，于是只报告“服务还没有可用模型”。这不是 xAI Chat Completions 地址或 Bearer 认证格式错误。

xAI 模型发现改用官方 `GET /v1/language-models`，只读取当前密钥可用的语言模型，并解析接口返回的输入模态、输出模态和上下文长度。模型列表响应同时兼容顶层数组、`data`、`models` 和 `items` 四种常见形状。

新建或编辑官方模型服务时，如果保存前仍没有模型，保存动作会自动执行模型发现；发现失败时保留编辑 Sheet 并显示供应商返回的错误，不保存不可用配置。已有零模型服务显示“待获取模型”，测试按钮改为“获取并测试”：先发现并启用返回的模型，再使用第一个模型发起最小聊天测试。这样旧配置可以原地修复，不需要删除重建。

自动检查使用虚拟密钥和模拟 xAI 响应，覆盖官方发现地址、Bearer 请求头、能力元数据、旧零模型服务修复、新建服务保存兜底以及后续聊天测试。没有使用用户密钥，没有发起真实 xAI 计费请求，也没有执行真机验收。
